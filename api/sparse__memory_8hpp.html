Detailed Description

Demand-allocated physical RAM backed by fixed-size pages.

SparseMemory models one or more physical RAM ranges inside the 32-bit address space without reserving host memory up front. Storage is carved into 4 KiB blocks that are allocated the first time they are written; reading a never-written location yields zero without allocating.

Backing pages vs. architectural pages
The 4 KiB block size is a host-side storage detail. It is invisible to simulated software and has no effect on timing. Architectural page sizes (Sv32 pages and megapages) belong to a future MMU/TLB model, which will translate virtual addresses before they ever reach physical memory.
Address validity
Only addresses inside a configured RAM range are accessible. Accesses outside every range fail with ok == false, exactly like an access past the end of a FlatMemory, so programs that run off the end of RAM still fault.
Thread safety
Not thread-safe: reads update an internal last-page lookup cache.
